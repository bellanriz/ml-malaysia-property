========================================================================
PROJECT DESCRIPTION
========================================================================

This project predicts property prices in Kuala Lumpur, Malaysia using
machine learning regression models. The dataset contains 53,000+ real
property listings with features like location, size, rooms, bathrooms,
parking, property type, and furnishing status.

Five regression algorithms are compared:
- Linear Regression (baseline)
- Ridge Regression (L2 regularization)
- Lasso Regression (L1 regularization)
- Random Forest Regressor (ensemble of decision trees)
- Gradient Boosting Regressor (sequential tree building)

The best model is selected based on R², MAE, and RMSE metrics.

------------------------------------------------------------------------
STEP 2: DATA PREPROCESSING
------------------------------------------------------------------------
File: src/data_preprocessing.py

What I did:
1. Cleaned Price column: "RM 1,250,000" → 1250000.0
   - Used regex to remove non-numeric characters
   - Converted string to float with pd.to_numeric()

2. Cleaned Size column: "Built-up : 1,335 sq. ft." → 1335.0
   - Same regex approach

3. Cleaned Rooms column: "3+1" → 3.0
   - Used str.extract() to get first number

4. Dropped rows where Price is missing (248 rows)
   - Can't train if we don't know the answer

5. Filled missing values:
   - Numeric columns (Bathrooms, Car Parks, Size, Rooms): filled with MEDIAN
   - Categorical columns (Furnishing, Property Type): filled with "Unknown"
   - WHY median not mean? Median is robust to outliers

6. Removed outliers:
   - Price < RM 100,000 or > RM 10,000,000 → removed
   - Size < 200 or > 10,000 sq.ft → removed
   - WHY? Extreme values confuse the model

7. Log-transformed Price:
   - df['Price_log'] = np.log1p(df['Price'])
   - WHY? Price is heavily right-skewed (most properties are cheap,
     few are very expensive). Log makes it more normally distributed,
     which helps all models learn better.

8. Encoded categorical variables:
   - Used LabelEncoder to convert text → numbers
   - Location: 111 unique values → numbers 0-110
   - Property Type: 98 unique values → numbers 0-97
   - Furnishing: 4 unique values → numbers 0-3

What I learned:
- Real data is MESSY — strings, missing values, outliers everywhere
- 90% of ML work is data cleaning, not model building
- Log transform is essential for skewed targets
- LabelEncoder converts categories to numbers for ML models
- Median is better than mean for filling missing values (outlier-robust)
- Always drop rows where the TARGET is missing (not features)

------------------------------------------------------------------------
STEP 3: MODEL TRAINING
------------------------------------------------------------------------
File: src/train_model.py

What I did:
1. Loaded cleaned data from kl_property_cleaned.csv
2. Split into 80% train, 20% test (train_test_split)
3. Scaled features using StandardScaler (for linear models)
4. Trained 5 different models
5. Evaluated each with R², MAE, RMSE
6. Found the best model
7. Showed feature importance from Random Forest
8. Saved best model to models/best_model.pkl

Models explained:
- LINEAR REGRESSION: Draws a straight line through the data.
  Simple, fast, interpretable. But can't capture complex patterns.

- RIDGE REGRESSION: Linear regression + L2 penalty.
  Prevents overfitting by shrinking coefficients.
  Good when you have many correlated features.

- LASSO REGRESSION: Linear regression + L1 penalty.
  Can zero out unimportant features entirely.
  Good for feature selection.

- RANDOM FOREST: Builds 100 decision trees on random subsets of data,
  averages their predictions. Handles non-linear patterns.
  Doesn't need feature scaling.

- GRADIENT BOOSTING: Builds trees sequentially. Each new tree tries
  to fix the errors of the previous ones. Usually the strongest
  model but slower to train.

What I learned:
- train_test_split: 80% for learning, 20% for honest evaluation
- StandardScaler: Normalizes features to mean=0, std=1
  (needed because Size~1000 but Rooms~3, linear models get confused)
- Tree-based models (Random Forest, Gradient Boosting) DON'T need scaling
- R² Score: 1.0 = perfect, 0.0 = useless (just predicting the mean)
- MAE: Average prediction error in RM — easy to interpret
- RMSE: Like MAE but penalizes big errors more
- Feature importance: Shows which features the model relies on most
- joblib: Saves trained models to disk so you don't retrain every time

========================================================================
KEY CONCEPTS SUMMARY
========================================================================

REGRESSION vs CLASSIFICATION:
- Regression: Predict a continuous number (price = RM 500,000)
- Classification: Predict a category (spam/not spam, cat/dog)

OVERFITTING vs UNDERFITTING:
- Overfitting: Model memorizes training data, fails on new data
- Underfitting: Model is too simple, can't learn the patterns
- Solution: Train/test split, regularization (Ridge/Lasso)

FEATURE ENGINEERING:
- Creating new useful features from raw data
- Example: Price_per_sqft = Price / Size
- Log transform of skewed variables

EVALUATION METRICS:
- R² (R-squared): % of variance explained. Higher = better.
- MAE (Mean Absolute Error): Average error in same units as target.
- RMSE (Root Mean Squared Error): Like MAE but penalizes big errors.

THE ML PIPELINE:
1. Get data
2. Clean data (80% of the work!)
3. Feature engineering
4. Split train/test
5. Train models
6. Evaluate & compare
7. Pick the best model
8. Deploy / predict on new data

COMMON ERRORS I ENCOUNTERED
========================================================================

1. ModuleNotFoundError: matplotlib version incompatible with Python 3.14
   Fix: Remove version pins in requirements.txt

2. KeyError: 'Price_log' not in index
   Fix: Run data_preprocessing.py BEFORE train_model.py
   (preprocessing creates the Price_log column)

3. AttributeError: '_name_' vs '__name__'
   Fix: Python dunder attributes need DOUBLE underscores: __name__

4. "python: command not found"
   Fix: Virtual environment deactivated. Run: source venv/bin/activate
   Or use: python3 instead of python

5. SyntaxError: feature_cols = (empty)
   Fix: Always assign a value when using =

6. Only 9 rows after preprocessing
   Fix: Run load_data.py first to get fresh raw data, then preprocess
